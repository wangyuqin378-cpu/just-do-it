# Just Do It

[English](README.md) · [工作流示例](EXAMPLES.md)

## 这是什么

一套把任务请求、会议纪要转成可跟踪行动的 Agent Skill 实验：识别哪些事与你有关，为每件事选择工作流，再保留执行结果。

仓库包含指令和文档模板，不是独立 App。**原始流程依赖内部工作平台、身份配置和组织服务**，只下载这个公开仓库无法独立运行。

## 怎么使用

可以先阅读和研究流程，这一步不需要服务权限：

1. 打开 [EXAMPLES.md](EXAMPLES.md)，看一条请求怎样分类、预期输出是什么。
2. 阅读 [SKILL.md](SKILL.md)，核对服务前提、身份变量和路由规则。
3. 查看[任务格式](TODO_LIST_FORMAT.md)与[文档模板](DOC_TEMPLATES.md)，了解记录方式。
4. 如果要适配自己的环境，先阅读[降级行为](FALLBACKS.md)，再为不可用的内部集成提供替代实现。

一个简化的流程示例：

```text
我要写完复盘文档，约一次对齐会，再找同事要上周的数据。
```

它会拆成文档任务、候选会议时间和消息草稿。需要确认的动作先等待确认，执行结果或尚未解决的步骤回到任务记录中。这里说明的是预期过程，不代表已经完成外部操作。

仓库不提供内部服务和凭据，因此没有适用于所有人的一键安装命令。没有兼容环境时，可把它作为工作流设计参考。

## 为什么做

会议纪要和零散消息里，经常混着自己的事、别人的事，以及还需要确认的事。直接抄成一个列表，容易丢掉这些区别。

这个实验想探索 Agent 怎样把信息接到后续行动：明确归属，选对工具，再留下能说明“实际做到了哪一步”的记录。
